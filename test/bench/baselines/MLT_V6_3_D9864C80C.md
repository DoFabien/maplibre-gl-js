# Baseline MLT 6.3 — protocole apparié

Cette baseline mesure le chemin MLT optimisé au commit produit
`d9864c80cf3197362428b30ba02ed5e8654c7f74`, avec Node 26.7.0 sur un Intel
Core i7-1260P. Le rapport complet est
`test/bench/baselines/mlt-v6.3-d9864c80c.json`.

## Protocole

- 47 cas individuels, chacun dans un nouveau processus, pour les durées, la
  mémoire et les compteurs de matérialisation ;
- 16 comparaisons MVT/MLT supplémentaires, chacune dans un processus dédié ;
- ordre MVT/MLT alterné à chaque itération dans une comparaison ;
- 10 warmups, puis 30 mesures conservées intégralement dans le JSON ;
- percentiles R7 avec interpolation linéaire ;
- ratios calculés par itération appariée avant de résumer médiane et p95 ;
- 20 requêtes par mesure pour les microbenchmarks query et trois décodages par
  mesure pour les corpus OMT.

Ce protocole empêche un p95 sur dix mesures de devenir le maximum et évite de
diviser deux queues de distribution provenant de processus soumis à des
fréquences CPU différentes.

Les requêtes très sélectives sont à parité ou plus rapides en MLT.

## Matérialisations

- parse et symboles points/lignes : zéro fallback, wrapper, objet de propriétés,
  `Point` ou partie géométrique matérialisée ;
- queries : les wrappers créés sont exactement les objets publics retournés ;
- query rendered rejetée : aucune géométrie chargée ;
- feature-state : aucun wrapper, objet de propriétés, objet de géométrie ou
  redécodage main-thread ;
- overzoom : aucun wrapper, `Point`, `Point[][]` ou réencodage MVT ;
- cycle de vie complet : 64 wrappers et 64 objets de propriétés pour 64 sorties
  publiques, sans matérialisation intermédiaire.

## Reproduction et garde CI

```bash
npm run bench:mlt-isolated -- --iterations 30 --warmup 10 \
  --output test/bench/results/mlt-current.json
npm run bench:mlt-check -- --report test/bench/results/mlt-current.json
```

Une seconde campagne complète indépendante a passé les 16 budgets normalisés,
les budgets mémoire/transfert et tous les invariants de matérialisation. Le job
nightly applique le même protocole et archive le rapport JSON de chaque commit.
