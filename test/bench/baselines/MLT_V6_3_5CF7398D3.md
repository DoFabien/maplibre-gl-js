# Baseline MLT 6.3 — Bing standard et FastPFOR explicite

Cette baseline mesure le commit
`5cf7398d3b2c2e67c0cfec4c7dab79df84540d92` avec Node 26.7.0 sur un Intel
Core i7-1260P. Le rapport complet et les échantillons bruts sont conservés
dans `test/bench/baselines/mlt-v6.3-5cf7398d3.json`.

## Correction du corpus

Le corpus Bing standard n'est pas encodé avec FastPFOR. La fixture MLT
`bing/4-12-6.mlt` est la sortie attendue non modifiée de
`maplibre-tile-spec` et ses métadonnées physiques contiennent uniquement
`NONE` et `VARINT`.

La couverture FastPFOR utilise désormais la fixture synthétique officielle
`props_u32_fpf_256.mlt`, générée explicitement avec `cfg().fastPFOR()`. Le
setup des benchmarks inspecte les métadonnées des streams et échoue si Bing
contient `FAST_PFOR` ou si la fixture synthétique n'en contient pas. Le nom du
fichier n'est donc plus utilisé comme preuve de la technique d'encodage.

## Protocole

- 60 cas individuels, chacun dans un nouveau processus ;
- 22 comparaisons MVT/MLT appariées et isolées ;
- ordre MVT/MLT alterné à chaque itération ;
- 10 warmups puis 30 mesures conservées ;
- percentiles R7 et ratios calculés échantillon par échantillon ;
- durées, débits, heap, ArrayBuffers, transfert et matérialisations mesurés.

Commande de reproduction :

```bash
npm run bench:mlt-isolated -- --iterations 30 --warmup 10 \
  --output test/bench/results/mlt-current.json
npm run bench:mlt-check -- --report test/bench/results/mlt-current.json
```

## FastPFOR explicite

Le cas `MltFastPforDecodeMLT` effectue 100 décodages complets par mesure pour
éviter que la petite fixture soit dominée par la résolution du chronomètre.
Sa médiane est de 31,175 ms par lot, soit environ 3 208 tuiles/s. Les
métadonnées observées sont `FAST_PFOR,NONE`.

Par itération, ce cas décode exactement 100 layers, 200 colonnes, 51 200
valeurs et 208 800 octets de colonnes, sans wrapper, objet `properties`,
`Point` ni range géométrique matérialisé.

## Matérialisations et mémoire

- les buckets `fill`, `line`, `circle`, `fill-extrusion` et `symbol` restent à
  zéro fallback, wrapper, objet `properties`, `Point` et range géométrique ;
- toutes les queries MLT restent à zéro wrapper intermédiaire ;
- les objets publics de query sont créés uniquement après sélection ;
- feature-state ne redécode pas le raw tile et ne matérialise aucune feature ;
- overzoom reste en MLT, sans `Point`, wrapper ni réencodage MVT ;
- la matrice 5/50/200 colonnes décode exactement les colonnes lues ;
- le cycle `load → query → feature-state → overzoom → reload` respecte les
  plafonds de heap, ArrayBuffers, transfert et mémoire retenue.

Le contrôle `bench:mlt-check` couvre 29 contrats de matérialisation ainsi que
tous les budgets mémoire et transfert. Tous les contrôles passent avec cette
baseline.
