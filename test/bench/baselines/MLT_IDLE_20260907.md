# Image finale des symboles avant `idle` — 7 septembre 2026

## Cause isolée et correctif commun MVT/MLT

L'écart SwiftShader du [lot styles précédent](MLT_STYLES_20260907.md) n'exige
ni `setStyle` ni décodage MLT : un aller-retour de caméra suffit. La dernière
image dessinée contenait encore des tuiles retenues pour le fondu des symboles.
Leur nettoyage, **après le dessin**, changeait les entrées du placement sans
demander de nouvelle frame ; la carte pouvait donc émettre `idle` sur une image
qui ne correspondait plus au jeu de tuiles courant.

Le correctif fait remonter un booléen de `TileManager.releaseSymbolFadeTiles()`
à `Style`, puis à l'ordonnanceur de `Map`. Une frame est demandée uniquement
si des tuiles ont effectivement été retirées, afin de recalculer le placement
et redessiner avant `idle`. L'ordre dessin/nettoyage reste inchangé ; tous les
gestionnaires de sources sont parcourus, même après le premier retrait.

Ce changement est commun à MVT et MLT. Il ne change ni le décodeur columnar,
ni les résultats GeoJSON, ni les images de référence, ni les tolérances.
Les archives des campagnes précédentes restent des échecs historiques.

## Réduction et contre-épreuves

Build production, quatre tuiles locales, canvas 800 × 600, DPR 1, un worker,
`fadeDuration: 0`, Chrome 152.0.7977.75 / SwiftShader. Chaque variante ci-dessous
est répétée deux fois en MVT et deux fois en MLT.

| Aller-retour caméra, avant correctif | Pixels différents au retour | Après un repaint explicite |
| --- | ---: | ---: |
| Toutes les couches | 46 | 0 |
| Sans symboles | 0 | 0 |
| Symboles ponctuels seuls avec le fond | 55 | 0 |
| Heatmap seule avec le fond | 0 | 0 |
| Toutes les couches sauf heatmap | 42 | 0 |

L'écart maximal vaut un niveau par canal. La lecture WebGL de la dernière
frame **avant `idle`** retrouve exactement les pixels de la capture écran :
ce n'est pas un artefact ajouté par la capture/composition du navigateur.
Les coordonnées de caméra non arrondies, les bounds et la projection du centre
restent identiques avant/après le repaint. Cela ne détermine pas quelle instruction
du pilote explique l'amplitude d'un niveau ; le défaut de cycle de rendu est,
lui, démontré indépendamment du GPU par les tests de tuiles.

- [Réduction initiale et variantes](browser-idle-isolation-before-20260907/camera/results.json).
- [Tests sans demande de frame](browser-idle-isolation-before-20260907/unit-without-followup.json) :
  deux échecs sur la différence entre les tuiles de la dernière frame et celles
  présentes à `idle`, avec `fadeDuration` 0 et 300, sur deux sources GeoJSON.
- Les mêmes tests passent avec le correctif ; un repaint supplémentaire ne
  change plus le jeu de tuiles et le nettoyage retourne alors `false`.
- [Replays corrigés](browser-idle-isolation-20260907/results.json) : huit sessions
  (repaint témoin / aller-retour × MVT/MLT × deux répétitions), **zéro pixel**
  différent avant le repaint diagnostique, dans la frame WebGL finale et après.

Un essai de nettoyage déplacé avant le dessin a été rejeté : il produisait
53 322 pixels différents, avec des labels manquants, car le placement avait encore
été calculé avec les tuiles retirées. Il n'est pas dans le correctif final.
Les premières observations ne lisaient que la frame après repaint : elles
masquaient le défaut et ne sont pas utilisées comme preuve de stabilité.

  passages SwiftShader stricts. **25/25 checkpoints MVT/MLT exacts** dans chaque
  campagne, en pixels et GeoJSON complet ; cinq cycles de styles supplémentaires.
- Dix compteurs worker interdits et `propertyProxyMisses` présents et nuls ;
  les assertions de durée de vie des sources et du feature-state restent inchangées.
- **3 730/3 730 tests unitaires**, **759/759 tests de build**,
  **178/178 tests d'intégration**, **243/243 rendus MLT stricts logiciel**.
- GPU complet : **1 887/1 923**, exactement les 36 échecs historiques,
  aucun nouveau ni disparu ; la commande reste en échec (code 1).
- Typecheck, lint ciblé et builds dev/prod/strict réussis. Le bundle main ajoute
  61 octets bruts (583 968), les bundles worker et partagé sont identiques au lot
  précédent ; la référence de taille et les quotas ne sont pas modifiés.
- Régressions navigateur : scénario base 7/7 et symboles 10/10 exacts.

## Reproduction

```bash
npm run build-prod
PUPPETEER_GPU=software node test/bench/e2e/mlt-render-isolation.ts \
  --journeys repaint,camera --read-idle --assert-stable --runs 2 \
  --output <nouveau-dossier>
```

Sans `--assert-stable`, le statut `diagnostic-complete` signifie seulement que
les observations ont été collectées, même si elles diffèrent. Avec ce flag,
toute différence exacte échoue. `--layers background,poi-labels` réduit les
couches ; cette option est réservée aux parcours caméra/repaint pour ne pas
masquer un défaut par une remise en visibilité après changement de style.

Les sondes utilisent les API publiques de caméra/style et `readPixels` pendant
`render`. Le parcours original `mlt-lifecycle.ts` ne demande aucun repaint
diagnostique supplémentaire : ses assertions initial/final restent intactes.

## Limites et suite

Aucune nouvelle mesure de performance, de mémoire GPU ou de fuite n'est faite.
Des campagnes de correction peuvent tourner en parallèle ; leurs durées ne
sont pas des benchmarks. Une frame supplémentaire au nettoyage a un coût qui
n'a pas été quantifié ici, et n'est pas ajoutée aux repaints stables.

La suite logique est d'étendre le parcours navigateur aux transitions globe et
terrain, avec les mêmes contrôles de géométrie, feature-state et worker strict.
Cela reste à faire ; ce correctif ne certifie pas tous les styles ou pilotes.
