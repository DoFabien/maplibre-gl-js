# Baseline MLT 6.3 — couverture complète des buckets et FastPFOR

> Baseline historique : le cas nommé « Bing FastPFOR » utilisait une tuile
> Bing réencodée avec cette option, et non la fixture Bing standard. La
> baseline courante sépare les deux corpus et vérifie leurs métadonnées
> physiques ; voir `MLT_V6_3_5CF7398D3.md`.

Cette baseline mesure le commit
`b5b531691062a1bb7c7678235a6bf267c36c736e` avec Node 26.7.0 sur un Intel
Core i7-1260P. Le rapport complet et les échantillons bruts sont conservés
dans `test/bench/baselines/mlt-v6.3-b5b531691.json`.

## Protocole

- 59 cas individuels, chacun dans un nouveau processus ;
- 22 comparaisons MVT/MLT appariées et isolées ;
- ordre MVT/MLT alterné à chaque itération ;
- 10 warmups puis 30 mesures conservées ;
- percentiles R7 et ratios calculés échantillon par échantillon ;
- durées, débits, heap, ArrayBuffers, transfert et matérialisations mesurés.

Deux paires du run initial (`parse-only` et `end-to-end`) ont été relancées
après des outliers de scheduling en p95. Le JSON conserve cette provenance
dans `comparisonSampling` ; les compteurs et métriques non appariés restent
ceux du run complet.

Commande de reproduction :

```bash
npm run bench:mlt-isolated -- --iterations 30 --warmup 10 \
  --output test/bench/results/mlt-current.json
npm run bench:mlt-check -- --report test/bench/results/mlt-current.json
```

Le nouveau corpus Bing décode réellement, par itération, 30 layers, 159
colonnes, 1 641 valeurs et 2 991 138 octets de colonnes. Le benchmark force
l'accès à toutes les géométries et propriétés de la tuile encodée avec
FastPFOR et FSST ; il ne peut donc pas se limiter au scan lazy.

## Matérialisations et mémoire

- les buckets `fill`, `line`, `circle`, `fill-extrusion` et `symbol` restent à
  zéro fallback, wrapper, objet `properties`, `Point` et range géométrique ;
- toutes les queries MLT restent à zéro wrapper intermédiaire ;
- les objets publics de query sont créés uniquement après sélection ;
- feature-state ne redécode pas le raw tile et ne matérialise aucune feature ;
- overzoom reste en MLT, sans `Point`, wrapper ni réencodage MVT ;
- la matrice 5/50/200 colonnes décode exactement les colonnes lues ;
- le cycle `load → query → feature-state → overzoom → reload` respecte les
  plafonds de heap, ArrayBuffers, transfert et mémoire retenue.

Le contrôle `bench:mlt-check` couvre désormais 28 contrats de matérialisation
ainsi que tous les budgets mémoire et transfert. Les seuils de non-régression
utilisent cette baseline pour les cinq familles de buckets, Bing/FastPFOR et
les scénarios déjà couverts.
